# 结构化表达 (Structured Expression)

## 核心原理

```
思考（混沌） → 结构（骨架） → 表达（血肉） → 受众理解

     散点知识           逻辑框架           有序输出
  ┌─────────┐       ┌─────────┐       ┌─────────┐
  │ idea A  │       │ 结论先行 │       │ 结论    │
  │ idea B  │  →   │ 分类清晰 │  →   │ 论点1   │
  │ idea C  │       │ 有理有据 │       │ 论点2   │
  └─────────┘       └─────────┘       └─────────┘
```

## 经典框架

### 金字塔原理 (Pyramid)

```
           [核心结论]
              / \
             /   \
       [论点1]   [论点2]
          |        |
       [论据A]  [论据C]
       [论据B]  [论据D]
```

**写作规则**：
1. 结论先行
2. 以上统下
3. 分类清晰
4. 逻辑递进

### STAR 叙事法 (Situation-Task-Action-Result)

| 部分 | 问题 | 内容 |
|------|------|------|
| S - 情境 | 背景是什么？ | 当时的场景 |
| T - 任务 | 目标是什么？ | 要完成什么 |
| A - 行动 | 做了什么？ | 具体措施 |
| R - 结果 | 达成了什么？ | 量化成果 |

### 现象-原因-对策

```
[现象] 看到了什么？
   ↓
[原因] 为什么发生？（3层 Why）
   ↓
[对策] 怎么解决？
   ↓
[行动] 下一步做什么？
```

### PREP (Point-Reason-Example-Point)

```
P - Point:     亮出观点
R - Reason:    解释原因
E - Example:   举例说明
P - Point:    重申观点
```

## 场景适配

### 1. 正式汇报
```
结构：背景 → 目标 → 现状分析 → 方案 → 资源需求 → 风险 → 预期成果
重点：数据支撑、逻辑严谨、结论明确
注意：控制时长，预留Q&A
```

### 2. 日常邮件
```
结构：结论 → 背景（1句） → 详情 → 行动项（明确人+时间）
重点：简洁、专业、行动导向
注意：标题即摘要
```

### 3. 演讲/汇报
```
结构：开场（hook）→ 框架预览 → 主体（3点） → 总结 → 号召行动
重点：故事性、节奏感、记忆点
注意：一张图/表胜千言
```

### 4. 决策建议
```
结构：问题定义 → 现状 → 方案对比 → 推荐方案 → 实施路径 → 风险预案
重点：利弊清晰、推荐明确
注意：数据+直觉结合
```

## 表达质量检查清单

### 自检问题
- [ ] 结论是否在第一句？
- [ ] 每个观点是否有支撑？
- [ ] 分类是否互斥且完整？
- [ ] 逻辑是否顺畅无跳跃？
- [ ] 受众是否能复述核心观点？
- [ ] 是否有过度解释或解释不足？

### 精简检查
```
原文 → 删除 → 精简版
"我觉得可能大概" → 删除 → "......"
"从某种程度上来说" → 删除 → "......"
```

## 练习

### 练习1: 电梯演讲
你在电梯里遇到CEO，有30秒说服他批准你的项目。
- 用金字塔原理
- 30秒 = 3句话

### 练习2: 会议纪要转换
将混乱的会议讨论转化为结构化纪要：
1. 提取3个核心决策
2. 列出5个行动项
3. 标注负责人
