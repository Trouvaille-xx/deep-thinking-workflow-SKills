# 批判性思维 (Critical Thinking)

## 核心框架

```
证据 → 论证结构 → 隐含假设 → 逻辑谬误 → 结论可靠性
  ↓         ↓          ↓          ↓          ↓
  支持度   有效性     前提真实性   常见陷阱    置信度
```

## 评估维度

### 1. 证据质量评估
| 等级 | 类型 | 可靠性 |
|------|------|--------|
| ★★★ | 同行评审研究、多源数据 | 高 |
| ★★☆ | 单一样本、案例分析 | 中 |
| ★☆☆ | 传闻、个人经验 | 低 |

### 2. 论证结构检查
- **演绎论证**: 前提真 → 结论必然真
- **归纳论证**: 前提真 → 结论概率真
- **类比论证**: 相似性 → 可迁移性

### 3. 常见逻辑谬误清单

#### 形式谬误
| 谬误名称 | 模式 | 示例 |
|---------|------|------|
| 肯定后件 | A→B, B, 所以A | 鸟儿会飞，这东西会飞，所以它是鸟 |
| 否定前件 | A→B, ¬A, 所以¬B | 如果下雨地会湿，没下雨，所以地不湿 |

#### 非形式谬误
| 谬误名称 | 描述 | 识别关键词 |
|---------|------|-----------|
| 稻草人 | 攻击弱化后的观点 | "所以你认为..." |
| 诉诸权威 | 权威≠正确 | "专家说..." |
| 诉诸情感 | 情感≠事实 | "可怜的小..." |
| 虚假两难 | 只给两个选项 | "不是...就是..." |
| 滑坡谬误 | 无限推演 | "如果...就会..." |
| 循环论证 | 结论含前提 | "因为...所以..." |

## 扩展方法

### 4. 价值澄清 (Value Clarification)

区分表面诉求与深层价值观，识别决策的真实驱动力。

```
表层需求 → 深层价值 → 核心利益

"要一辆车"     →  "自由/便捷"     →  "掌控自己的时间"
"要涨薪"       →  "被认可/安全"   →  "自我价值实现"
"要买房"       →  "稳定/归属"     →  "家庭安全感"
```

**价值澄清协议**：
```
1. 列出所有相关方的表面诉求
2. 追问"为什么这个对你重要？"
3. 重复追问5次，直到触及核心价值
4. 识别不同诉求背后的共同价值
5. 寻找能同时满足多方核心价值的方案
```

**价值冲突矩阵**：

| 利益方 | 表面诉求 | 深层价值 | 潜在冲突 |
|--------|---------|---------|---------|
| 用户 | 免费使用 | 占便宜/便利 | 与商业化冲突 |
| 员工 | 高工资 | 安全感/成就感 | 与成本控制冲突 |
| 股东 | 高利润 | 投资回报 | 与长期投入冲突 |

### 5. 事实与观点剥离 (Fact-Opinion Separation)

将信息分解为可验证的事实与主观诠释，避免认知混淆。

```
信息混合物
    ├── 事实 (Fact)     → 可验证、真假分明
    └── 观点 (Opinion)   → 主观判断、可辩论
         ├── 解释        → 对事实的解读
         ├── 推断        → 基于事实的推测
         └── 评价        → 带情感色彩的判断
```

**剥离检查清单**：

| 检查项 | 事实特征 | 观点特征 |
|--------|---------|---------|
| 可验证性 | 有数据/来源 | 无法直接验证 |
| 真假 | 对或错 | 无对错之分 |
| 共识度 | 专家普遍认同 | 存在分歧 |
| 表达词 | "是"、"数据表明"、"研究显示" | "我认为"、"通常"、"大概" |

**分离协议**：
```
1. 划出所有陈述句
2. 标注每个句子的依据来源
3. 识别主观词汇（"重要的"、"更好的"、"正确的"）
4. 将信息重新标注为：
   - [F] 事实（附置信度）
   - [O] 观点（附支持度）
   - [F→O] 基于事实的推断（区分度）
5. 检查是否有观点伪装成事实
```

**常见伪装模式**：

| 伪装类型 | 原文示例 | 识别信号 |
|---------|---------|---------|
| 权威引用 | "专家说这个不行" | 未指明哪位专家 |
| 数据选择 | "90%的用户满意" | 未说明样本量/条件 |
| 趋势外推 | "增长放缓意味着衰落" | 相关≠因果 |
| 历史类比 | "这就像2008年..." | 情境差异被忽略 |

### 6. 第一性原则 + 5Why追问 (First Principles & 5-Why)

从现象追问到不可约的底层原理，穿越表象抵达本质。

```
第一性原理思维：

现象层：你看到的问题                          WHY层
     ↓                                              ↓
表象层：直接原因 / 表层机制                   Why 1
     ↓                                              ↓
中间层：结构性原因 / 系统机制                 Why 2
     ↓                                              ↓
本质层：第一性原理 / 不可约事实               Why 3-5
     ↓                                              ↓
新方案：从本质出发重新设计                    ↓
                                              Why N...
                                         (直到无法再追问)
```

**5Why 追问协议**：
```
问题陈述：[描述当前观察到的问题]

Why 1: 为什么会发生？
→ [直接原因]

Why 2: 为什么这个原因存在？
→ [系统/结构原因]

Why 3: 为什么这个结构会导致这个问题？
→ [更深层机制]

Why 4: 为什么这个机制是这样设计的？
→ [历史/路径依赖]

Why 5: 为什么会存在这样的设计前提？
→ [第一性原理]
```

**与第一性原则结合**：

| 层次 | 追问方向 | 示例（产品失败案例） |
|------|---------|------------------|
| 现象 | "出了什么问题？" | 用户流失率上升 |
| Why 1 | "为什么用户流失？" | 功能太复杂 |
| Why 2 | "为什么功能复杂？" | 需求变更频繁 |
| Why 3 | "为什么需求频繁变更？" | 缺乏用户研究 |
| Why 4 | "为什么不做用户研究？" | 快速上线压力 |
| Why 5 | "为什么要快速上线？" | [第一性] 团队认为速度>质量 |
| 重构 | "如果放弃速度优先..." | 引入用户验证流程 |

**检查点**：
- [ ] 每次追问都基于上一次回答
- [ ] 区分"因为我想要"和"因为本质如此"
- [ ] 直到回答变为"这就是系统的本质，无法再追问"

## 思考协议

### 快速评估 (30秒)
```
1. 结论是什么？(用一句话复述)
2. 最强的证据是什么？
3. 最弱的环节在哪里？
4. 置信度: ___/10
```

### 深度分析 (2分钟)
```
1. 列出所有隐含假设
2. 每个假设为真的概率？
3. 反例存在吗？
4. 如果假设为假，结论还成立吗？
5. 更强的替代结论是什么？
```

## 练习题目

1. "大多数成功企业家都是大学辍学者，所以你应该辍学去创业。" 分析这个论证。
2. "这款牙膏被全国牙医推荐，所以是最好的牙膏。" 识别谬误。
3. "我认识的每个人都喜欢X，所以X一定很受欢迎。" 评估证据质量。
4. "为什么这个项目总是延期？" 用5Why追问到本质。
5. 分析"用户说要免费功能"背后的真实价值诉求。
