# 设计学视角 (Design Perspective)

## 核心思维

### 1. 设计思维流程 (d.school)
```
     共情 (Empathize)
         ↓
     定义 (Define)
         ↓
     构思 (Ideate)
         ↓
   原型 (Prototype)
         ↓
     测试 (Test)
         ↓
     ↺ 迭代 ↺
```

### 2. 以人为本的设计原则
```
1. 人 > 技术
2. 行为 > 功能
3. 整体 > 局部
4. 可能性 > 现实性
5. 理解 > 美观
```

### 3. 设计五要素
```
战略层 (Why)    → 品牌/定位/价值主张
范围层 (What)   → 功能/内容需求
结构层 (How)    → 信息架构/交互逻辑
框架层 (How)    → 界面/导航/内容布局
表现层 (Look)   → 视觉/排版/配色
```

## 核心分析维度

### 1. 用户体验分析

**用户体验层次模型**：

```
        表现层
       (视觉/触感)
           ↑
        框架层
       (导航/布局)
           ↑
        结构层
       (信息架构)
           ↑
        范围层
       (功能/内容)
           ↑
        战略层
       (用户需求/商业目标)
```

**用户体验评估框架**：

| 维度 | 问题 | 权重 |
|------|------|------|
| 可用性 | 能完成任务吗？ | 高 |
| 可访问性 | 能被所有人使用吗？ | 中 |
| 可找到性 | 能找到想要的吗？ | 高 |
| 可靠性 | 值得信赖吗？ | 高 |
| 情感化 | 用起来开心吗？ | 中 |
| 有意义 | 对用户真正重要吗？ | 高 |

### 2. 共情地图 (Empathy Map)

```
        我 说/做
       ↗       ↘
   我 思          我 看/听
   想/感          (外在)
      ↖       ↗
        我 痛/获
       (内在需求)
```

**共情问题清单**：

| 维度 | 看/听 | 说/做 | 想/感 | 痛/获 |
|------|-------|-------|-------|-------|
| 用户看到什么？ | ✓ | | | |
| 用户说什么/做什么？ | | ✓ | | |
| 用户想什么/感受如何？ | | | ✓ | |
| 用户怕什么/想要什么？ | | | | ✓ |

### 3. 用户旅程地图 (User Journey Map)

```
阶段:    发现 → 考虑 → 评估 → 购买 → 使用 → 留存
         ↓       ↓       ↓      ↓      ↓      ↓
行为:   [具体行为]        触点: [接触点]
         ↓       ↓       ↓      ↓      ↓      ↓
情感:   😰 → 😐 → 😊 → 😃 → 😊 → 😢
         ↓       ↓       ↓      ↓      ↓      ↓
痛点:   [痛点1]        [痛点2]     [痛点3]
         ↓       ↓       ↓      ↓      ↓      ↓
机会:   [优化机会]
```

### 4. 形态美学分析

| 形态要素 | 设计传达 | 案例 |
|---------|---------|------|
| 线条 | 稳定/动态/柔和/硬朗 | 几何 vs 曲线 |
| 形状 | 圆润=亲和/方正=专业 | 图标设计 |
| 色彩 | 情绪/品牌/层次 | 品牌色系 |
| 质感 | 科技/自然/温度 | 材质设计 |
| 留白 | 呼吸/聚焦/高级 | 极简风格 |

**视觉层次原则**：
```
1. 最重要的元素最突出
2. 相关元素视觉分组
3. 元素间有清晰关系
4. 减少不必要的视觉元素
```

## 设计方法工具箱

### 1. 快速原型技术

| 技术 | 适用阶段 | 保真度 | 速度 |
|------|---------|--------|------|
| 纸质原型 | 早期概念 | 低 | 快 |
| 草图 | 想法探索 | 低 | 快 |
| 线框图 | 结构验证 | 中 | 中 |
| 交互原型 | 流程验证 | 中高 | 中 |
| 高保真原型 | 最终验证 | 高 | 慢 |

### 2. 创意技巧

**SCAMPER**：
```
S: Substitute  - 替代什么？
C: Combine     - 组合什么？
A: Adapt       - 怎么适应？
M: Modify      - 修改什么？
P: Put other use - 还有其他用途吗？
E: Eliminate   - 删除什么？
R: Reverse    - 反过来呢？
```

**脑力书写 (Brainwriting) 6-3-5**：
```
6人 × 3个想法 × 5分钟 = 90个想法
```

### 3. 设计验证方法

| 方法 | 验证内容 | 样本量 | 周期 |
|------|---------|--------|------|
| 可用性测试 | 任务完成率 | 5-8人 | 短 |
| A/B测试 | 方案优劣 | 大样本 | 中 |
| 问卷调查 | 态度/满意度 | 100+ | 中 |
| 访谈 | 深度洞察 | 5-10人 | 长 |
| 数据分析 | 实际行为 | 全量 | 持续 |

## 设计提案框架

### 1. 问题定义 (How Might We...)
```
HMW (How Might We) 问题写法:

原问题: 用户流失率高
       ↓
HMW问题: 
- HMW降低用户的决策焦虑？
- HMW让用户感受到产品的价值？
- HMW让用户形成使用习惯？
```

### 2. 概念设计表达
```
概念名称: [清晰、有意义]
       ↓
概念描述: [一句话说明核心价值]
       ↓
用户价值: [谁？什么痛点？怎么解决？]
       ↓
核心机制: [怎么运作？]
       ↓
差异化: [与现有方案的区别？]
```

### 3. 设计方案展示
```
设计原则 → 核心概念 → 关键场景 → 交互细节

1. 设计原则 (Design Principles)
   - 第一原则: ...
   - 第二原则: ...

2. 核心概念 (Core Concept)
   [视觉化呈现]

3. 关键场景 (Key Scenarios)
   - 场景1: [什么情况下]
     → [用户做什么]
     → [产品如何响应]

4. 交互细节 (Interaction Details)
   [交互原型/说明]
```

## 分析协议

### 快速设计分析 (2分钟)
```
1. 用户是谁？核心痛点是什么？
2. 现在的体验哪里不好？
3. 理想状态是什么样的？
4. 可能的解决方案方向？
```

### 深度设计研究 (10分钟)
```
1. 用户研究
   - 深度访谈
   - 观察分析
   - 数据挖掘

2. 共情建模
   - 用户画像
   - 共情地图
   - 旅程地图

3. 需求定义
   - HMW问题
   - 设计机会点
   - 优先级

4. 概念设计
   - 创意发散
   - 概念收敛
   - 原型制作

5. 设计验证
   - 可用性测试
   - 迭代优化
```

## 练习题

### 练习1: 重新设计登录流程
- 当前用户旅程中的痛点？
- 情感曲线最高/最低点？
- HMW问题定义？
- 最小可行解决方案？

### 练习2: 品牌视觉升级
- 现有品牌的核心价值？
- 目标用户感知如何？
- 升级方向建议？
- 风险点？
